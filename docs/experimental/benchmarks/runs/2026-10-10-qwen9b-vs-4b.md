# Local models vs gpt-oss 20b — 2026-10-10

Question: does a bigger local model justify a 12GB GPU (RTX 3060) upgrade?

## Setup

- Box: GTX 1660 Super 6GB, Ryzen 5 3600X, 16GB RAM. The 9b spills to CPU.
- Models: `qwen-context:h-q4_0-24k` (H), `qwen3.5:9b`, `qwen2.5-coder:7b`, `code-scout:4b` (all Q4_K_M weights) and `gpt-oss:20b-cloud` (same weights as local gpt-oss-20b; cloud latency only).
- Limits per call: H uses saved settings. Others use `num_ctx` 32768 (24576 overflowed: no pinned tokenizer, so byte accounting), output 8192 (code) / 2048 (scout).
- Local code tests use H sampling: temp 0.2, top_p 0.9, top_k 40, seed 42. gpt-oss used its defaults.
- Same in-process calls as the MCP tools (`runLocalExploreRepo`, `generateResult`), thinking off, run sequentially at commit `fd103a0`.
- Tests: 5 historical H failures + 2 hard H passes, picked from `field-feedback.md` and run docs. T3/T4 prompts are reconstructed; originals were not saved.
- Single run per cell. Treat small gaps as noise.

## KV cache trap

The daemon first ran with `OLLAMA_KV_CACHE_TYPE=q4_0` (`zz-qwen-benchmark.conf` overrode q8_0). Under q4_0, qwen2.5-coder:7b produced gibberish free text even in direct `/api/generate` calls; only JSON-constrained scout output survived. The override was removed and the local models were rerun with q8_0 KV. The table below is the q8_0 run.

## Earlier runs (q4_0 KV, superseded)

- 9b at its default sampling (temp 1, presence 1.5) crashed T3 and failed T6. Keep temp low in any Modelfile.
- code-scout:4b: T1 input overflow, T2 21 junk lines, T3 crash, T6 fail; near pass on T4. Not better than H. Not rerun.

## Findings

- No local model that fits this box beats H. The 9b and coder 7b trade wins with it; all three fail T4.
- gpt-oss 20b is a clear step up: 6/7 clean, and it alone passed T4 and abstained without junk. Its T1 miss is selection format, not missing knowledge.
- A 3060 would only make the 9b faster, not smarter. The upgrade case rests on 20B-class models. gpt-oss-20b local is ~13GB (MXFP4), so 12GB still needs light offload; a 16GB card avoids it. Local speed is unmeasured.
- Keep the daemon on q8_0 KV. q4_0 KV broke qwen2-family free text.
- Historical H failures T5 and the T1 resolver omission no longer reproduce; later deterministic work fixed them.
- Possible regression: T1 packing no longer includes the `src/index.ts` registration guards, so 4/9 gold lines are unreachable for any model.
